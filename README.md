# Пекло

Личный агрегатор календарей: веб на Python и отдельное Android-приложение. Ранее назывался «Рядом». Веб — просмотр и напоминания. Android — также создание/редактирование одиночных встреч, настраиваемые напоминания, копирование сателлитов и публикация для системных виджетов.

## Структура и документы
- [Веб-клиент](ics-monitor/README.md) — Exchange EWS, Яндекс CalDAV, опубликованные ICS; один источник каждого типа.
- [Android-клиент](android-calendar/README.md) — Exchange, Яндекс, системные календари Android (включая Google).
- [Правила](AGENTS.md), [запросы](REQUESTS.md), [спецификация](SPEC.md), [бэклог](BACKLOG.md), [изменения](CHANGELOG.md), [проверки](RUNLOG.md).

Оба клиента — один самостоятельный [репозиторий GitHub](https://github.com/Kwentar/peklo), основная ветка `main`; актуальная Android 0.5.1 находится в `codex/calendar-backlog`. SSH: `git@github.com:Kwentar/peklo.git`. Карточка мета-проекта: `projects/peklo/README.md`, ключ локальных настроек `projects.peklo`; мета-проект распространяется отдельно.

## Запуск веба — macOS
Нужен Python 3.9+ (для новой установки рекомендуется 3.11+) и pip. Из корня репозитория:

```sh
cd ics-monitor
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

Открыть http://127.0.0.1:8766/ и оставить процесс работающим. Для настроенного окружения доступен двойной клик по `ics-monitor/Запустить.command`. Если вкладка открылась раньше запуска сервера, обновить её. Подключения сохраняются в системном хранилище паролей и восстанавливаются после запуска; события загружаются заново. VPN требуется только если сервер доступен через него.

В форме Exchange ввести собственный адрес вида `https://mail.example.org/EWS/Exchange.asmx` (это пример, не рабочий сервер), логин и пароль. Можно указать только HTTPS-хост — стандартный путь EWS добавится. Произвольные пути, userinfo, query, fragment, HTTP и порты кроме 443 отклоняются. Редиректы запрещены, сертификаты проверяются. Яндекс подключается паролем приложения CalDAV. Учётные данные не прописываются в коде.

## Запуск веба — Windows / PowerShell
Инструкция подготовлена, запуск на Windows не проверен. Установить Python 3.9+ с pip:

```powershell
cd ics-monitor
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

Адрес и подключение календарей такие же. Пакет `tzdata` обеспечивает базу часовых поясов. macOS-окружение `.venv` не копировать на Windows — создать заново.

## Android: сборка и установка
Нужны JDK 17, Gradle 8.9 и Android SDK (platform 35, build-tools 34.0.0 для AGP 8.7.3). Указать `JAVA_HOME` и `ANDROID_HOME` либо локальный `android-calendar/local.properties` с `sdk.dir`. SDK и ключи не коммитятся. Gradle wrapper пока отсутствует — требуется установленный Gradle 8.9. Подробнее: [Android README](android-calendar/README.md).

macOS:
```sh
cd android-calendar
./build.sh
```
Скрипт использует локальное `tooling/`, если оно есть, иначе `gradle` из PATH. На чистом клоне зависимости инструментов установить самостоятельно.

Windows / PowerShell (не проверено):
```powershell
cd android-calendar
gradle :app:assembleDebug :app:testDebugUnitTest --console=plain
```

Результат: `android-calendar/app/build/outputs/apk/debug/app-debug.apk`. Установка на подключённый тестовый телефон: `adb install -r android-calendar/app/build/outputs/apk/debug/app-debug.apk` из корня. Для обновления необходима прежняя подпись; debug-ключ другого компьютера не заменит установленное приложение. Не удалять рабочую установку ради теста без сохранения нужных настроек.

Версия исходников Android в этой ветке: 0.5.0 (сборка 11). Package ID `ru.ryadom.calendar` сохранён для совместимости. При обновлении с 0.4.4 до 0.4.5 установить APK поверх существующей и обновить расписание; переподключение не требуется. Пользователь подтвердил восстановление Exchange (RUN-011). Для старого Exchange-аккаунта без сохранённого адреса сервера открыть «Календари → Войти снова», указать сервер и учётные данные. До этого автоопрос такого аккаунта останавливается без сетевого запроса. Новое название приложения — «Пекло». Виджет 0.4.6 поддерживает переключение дней, выбор даты, сжатые перерывы и прокрутку при нехватке места; группировки больше нет. Подробности визуальной проверки — в Android README.

## Проверки
Из `ics-monitor`:
```sh
.venv/bin/python -m unittest discover -p 'test_*.py'
```
В Windows использовать `.\.venv\Scripts\python.exe`. Тесты используют искусственные события и mock-ответы, без входа в рабочие календари. Android-тесты запускаются командой сборки выше. Эмуляторные/телефонные тесты `androidTest` запускать только на пустом тестовом устройстве: они записывают синтетические данные приложения.

Результаты текущих проверок и непроверенное — [RUNLOG](RUNLOG.md).

## Что хранится локально
Веб: подключения — macOS Keychain / Windows Credential Locker (keyring); события и журнал — в памяти процесса. «Отключить» удаляет сохранённое подключение. При недоступном хранилище подключение возвращает ошибку, открытого файла с паролями нет. Android: зашифрованный кэш и аккаунты на устройстве, резервное копирование отключено. Файлы `.env`, ключи, local.properties, окружения, tooling, сборки, APK, dist, логи и локальные данные исключены Git; не добавлять их через `git add -f`.

Старые APK в `android-calendar/dist/` сохранены только локально: они содержат прежнюю конфигурацию и не являются очищенными сборками. Не загружать их в публичные релизы. Бинарники вообще не входят в подготовленный коммит. Полный аудит содержимого игнорируемых SDK, кэшей и пользовательских данных не заявляется.

## Ограничения
Google OAuth в вебе не реализован. Android не гарантирует опрос каждые 5 минут: фоновые задания от 15 минут могут откладываться ОС. Политики SSO/OAuth конкретного Exchange могут не поддерживать текущую Basic Auth. Windows и физический телефон на этом этапе не проверены. Лицензия пока не выбрана.
